## 一、现在的架构（2026-11 定下来的）

**一个后端，两个前台，一份数据库。**

```
手机 / 外网 --Funnel(https)--> 容器 lexica:127.0.0.1:8081 ┐
                                                         ├─> 同一个后端 127.0.0.1:8766 ──> 数据库（宿主机目录，挂进容器）
家里电脑 --http--> PVE 宿主机:80 (/word-puzzle/api/) ─> 容器 <容器IP>:8082 ┘
```

| 入口 | 谁用 | 要登录吗 |
|---|---|---|
| 公网（Funnel，8081） | 学生、老师 | 全部要登录 |
| 内网（8082，经 PVE 宿主机 的 `http://<服务器IP>/word-puzzle/` 或直连） | 家里 | **做题不用登录**（成绩按设备记）；点到管理功能（账号、题库、标签、访问记录）才要老师登录 |

- 区分入口靠 nginx 打的 `X-Wp-Entry: lan` 头：公网入口每次都把它清空，后端还要求请求来自本机 nginx 且开了 `WP_LAN_GUEST=1`。
- 数据库和备份**不放在容器里**：数据库在 PVE 宿主机 的 `/data01/lexica-data/`，备份在 `/data02/lexica-backup/`（另一块盘），
  都以挂载点挂进容器，容器本身可以随时销毁重建。每天北京时间凌晨 3 点自动备份，保留 30 份，备份后做完整性检查。
- 以前 PVE 宿主机 上那套独立的「家庭版」后端已退役（旧数据库文件原地保留当备份，不删）。

## 二、把其他学科放进来（化学、物理、话题、无线电）——接口已经留好

现状：这四个是纯静态页面，成绩只存在浏览器本地。开放到 Tailscale 时，只要照下面接，就自动有**同一套账号、访问记录、成绩**：

1. 在 `word-puzzle/server/modules.py` 的 `MODULES` 里把对应项 `enabled` 改成 `True`（登记表 `GET /api/modules` 会列出）。
2. 把静态页面放到容器的 nginx 下（`/chemistry/` 等，和 `/shared/` 同级），页头用共享的 `module-header.js`。
3. 页面里引入 `/word-puzzle/js/tracker.js`（只需要 `<meta name="wp-base">`）→ 访问、停留时间自动进访问记录。
4. 要登录：向 `/word-puzzle/api/auth/me` 问当前用户（同一个 Cookie）；没登录就跳 `/word-puzzle/login.html?next=…`。
5. 成绩 / 进度：`POST /word-puzzle/api/records`，`{"subject":"chemistry","kind":"quiz","payload":{…}}`（≤20 KB 的 JSON）；
   `GET /api/records?subject=chemistry` 学生取自己的、老师取全部（可加 `user_id=`、`kind=`）。内网未登录的人带 `device` 区分。
6. 权限判断统一走 `server/policy.py` 的 `allow(user, action, resource)`，资源里带上 `subject`，将来按学科给老师分权限不用改调用处。

还要做的（接入时）：每个学科页面把「本地 localStorage 成绩」换成 `POST /api/records`；`hub` 首页的入口改读 `/api/modules`；
学科页面的双语 / 配色 / 测试照 AGENTS.md §3 的规矩。

## 三、多个老师、不同权限（设计草案，还没做）

目标：老师 A 管初中英语 1–3 班，老师 B 管化学全部班级，你是总管。

**角色**：`owner`（总管，现在的 admin）、`teacher`（普通老师，按范围）、`assistant`（助教，只读成绩，可选）、`student`。

**范围表**（新表 `teacher_scopes`）：

| 列 | 含义 |
|---|---|
| `user_id` | 老师 |
| `kind` | `class`（班级）/ `bank`（题库）/ `subject`（学科）/ `tag`（标签） |
| `value` | 班级名 / 题库编号 / 学科 id / 标签 |
| `level` | `view`（只看）/ `manage`（可改） |

**判断规则**（都落在 `policy.allow`，调用处已经传了资源）：
- 题库：自己建的（`banks.owner_id` 已有）或被授予 `bank` 范围的可改；按 `subject` 范围授予的学科下全部题库可改。
- 学生 / 成绩 / 访问记录：只看得到班级在自己 `class` 范围里的学生；列表接口按范围过滤（账号列表、成绩汇总、访问记录、导出）。
- 标签：老师只能改自己范围内题库的标签，且只能用自己班级范围内的标签去开放。
- 名单导入：只能导入进自己负责的班级。
- 账号管理（建老师、改范围、重置密码）：只有 `owner`。

**做之前先做的两件事**：
1. 审计日志表 `audit_log(who, when, action, resource, detail)`：谁改了标签 / 删了题库 / 重置了密码——多人管理后必须有。
2. 列表接口先统一成「带 scope 过滤」的一个函数，别在每个接口里各写各的。

**测试要点**：老师 A 看不到 B 的班（接口、导出、访问记录各测一遍）；越权改题库返回 403；授予 / 收回范围立即生效；owner 不受限。

## 四、想做的好玩模块（按「吸引力 ÷ 成本」粗排，先记下，不承诺）

> 前提：成绩、访问记录、账号、通用记录接口（`/api/records`）都已经有了，下面大部分只是在它们上面做新的页面。

**词境（英语）**
1. **错词本 + 间隔复习**（成本低，价值最高）：答错的词自动进「我的错词本」，按遗忘曲线（Leitner 盒子）每天推 5 分钟复习。
2. **连续打卡 + 徽章**：连续天数、百词斩 / 千词斩、夜猫子等成就；首页一个火苗图标，断了会心疼。
3. **班级周榜 / 小组 PK**：按班级的周榜（可用昵称），同一套题限时对战；老师一键「发起班级挑战」，生成二维码。
4. **听写模式**：已有美式女声 TTS，加「听音拼写」和「听音选词」；摩尔斯 / 语速调节。
5. **语境填空**：用词的例句挖空选词，比单纯中英配对更接近真实用法。
6. **闯关地图**：一个单元一个岛，解锁动画、宝箱、小 Boss（限时一整单元混合）。
7. **老师学情看板**：易错词 TOP、班级热力图（谁几天没练）、「沉默学生」提醒；数据全来自现有的成绩和访问记录。
8. **家长周报**（家庭版）：每周一自动生成「孩子本周练了几次、新掌握多少词、最难的词」的一页，可打印。
9. **虚拟宠物 / 养成**：学习积分喂养小动物，每天有上限（防沉迷，也是设计的一部分）。

**其他学科**
10. **化学**：元素周期表记忆卡、方程式配平游戏、离子鉴定小侦探；**物理**：受力分析拖拽、电路搭建、抛体运动调参数看轨迹。
11. **无线电考试**：错题统计、**摩尔斯电码听写**（可以复用音频合成）、章节模拟卷、考前倒计时。
12. **每日话题**：家庭讨论打卡（今天聊了没有）、话题收藏、家长备注。
13. **成长档案**：跨学科的学习曲线和时间分布（`/api/records` 现成），期末一页总结。

**平台**
14. **PWA 安装 + 离线**（已有离线页，补 manifest 和缓存），手机像 App 一样装。
15. **微信小程序打通账号**（小程序已经有，登录改成同一套账号）。
16. **导入 / 导出 Anki**、自定义词表分享。
17. **AI 辅助**：作文批改、口语发音评分（涉及学生内容，上线前先想清隐私和费用）。
18. **运维看板**：服务健康、磁盘、备份是否成功、最近错误（给自己看）。

## 五、隐私与公开仓库（记着）

- 仓库是公开的：**代码和文档可以公开，数据不行**。真实数据只在本地（宿主机目录 + 备份盘），不进 git；
  `.gitignore` 挡住常见文件，`test_repo_hygiene.py` 在测试里再拦一道。
- 公开的信息里本来就有：Funnel 网址（要让学生访问，本来就公开）、内网 IP 段、服务器主机名。这些不算秘密，但别再往里加更多。
- 提交作者邮箱会随历史公开：只用个人邮箱（`git config user.email`），不用公司邮箱；见 AGENTS.md 的「Identity」。
- 访问记录（IP、设备）属于个人信息：只有老师账号能看，备份文件要和数据库一样保管。
