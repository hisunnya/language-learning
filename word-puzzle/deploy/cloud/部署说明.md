# 词境 Lexica · 云服务器（生产）部署说明

生产环境是一台云上的 Debian 服务器（学生版，要登录）。后端、数据库、备份都在这一台上，
nginx 直接面对公网，不再经过 Tailscale Funnel。家里的 PVE 是测试环境，开发 VM 做单元测试。

> 域名、服务器地址、密钥路径这类私有值**不写进仓库**，只放在本机的 `AGENTS.local.md` 和 `~/.ssh/config`。
> 下面用 `<服务器别名>`、`<域名>` 代替。

## 一、这套脚本做什么

| 脚本 | 做的事 | 什么时候跑 |
|---|---|---|
| `install.sh` | 复用 `deploy/family/install.sh` 装后端、数据库、systemd、每日备份、看门狗、管理命令；再装公网 nginx（只认 `<域名>`） | 每次发布 |
| `render-nginx.sh` | 生成公网 nginx 配置：有证书就开 HTTPS，没有就只放行证书验证 | 被前两个脚本调用，也可单独跑 |
| `harden.sh` | SSH 只许密钥登录 + fail2ban | 装好后一次 |
| `enable-tls.sh` | 签 Let's Encrypt 证书、打开 HTTPS、设置自动续期 | **备案通过**、域名解析到本机之后一次 |

没有证书之前，网站**只能从服务器本机访问**：登录用的 Cookie 带 `Secure`，明文 http 暴露在公网既登不上，
账号密码也会明文走公网。所以备案期间用 SSH 隧道测试。

## 二、第一次部署

在你的电脑上（路径换成自己的，别把代码打进公开仓库以外的地方）：

```bash
COPYFILE_DISABLE=1 tar czf /tmp/lexica-src.tgz --exclude='word-puzzle/var' --exclude='__pycache__' --exclude='.DS_Store' word-puzzle hub/shared
scp -q /tmp/lexica-src.tgz <服务器别名>:/tmp/lexica-src.tgz
ssh <服务器别名> 'mkdir -p /root/language-learning && tar xzf /tmp/lexica-src.tgz -C /root/language-learning && cd /root/language-learning && env DEBIAN_FRONTEND=noninteractive WP_DOMAIN=<域名> bash word-puzzle/deploy/cloud/install.sh'
```

不要在国内服务器上 `git pull`：到 GitHub 的连接又慢又不稳（实测一次请求要 8 秒）。代码从你的电脑或开发 VM 推过去。

装好后创建管理员：

```bash
ssh <服务器别名> 'wp-family-admin create-admin 你的工号 --name 你的名字'
```

## 三、备案期间怎么测试：SSH 隧道

```bash
ssh -L 8081:127.0.0.1:8081 <服务器别名>
```

保持这个终端不关，用 **Chrome** 打开 `http://127.0.0.1:8081/word-puzzle/`（Chrome 把 localhost 当作安全环境，
带 `Secure` 的 Cookie 能正常保存；Safari 不行）。服务只监听本机，没有对公网暴露。

不要用 `http://公网IP` 测试：80 端口在没有证书时只放行证书验证；而且在国内未备案就向公众提供服务不合规。
这里的做法是自己一个人通过隧道看，不对学生开放，直到备案通过。

## 四、SSH 加固（装好后一次）

```bash
ssh <服务器别名> 'cd /root/language-learning && bash word-puzzle/deploy/cloud/harden.sh'
```

- 脚本只在 root 的 `authorized_keys` 里已经有公钥时才继续，否则拒绝（防止把你锁在外面）。
- 它写 `/etc/ssh/sshd_config.d/00-lexica-hardening.conf`：关掉密码登录、`PermitRootLogin prohibit-password`。
  文件名以 `00-` 开头，是因为 sshd 取第一次出现的值，要排在腾讯云自带的 `50-cloud-init.conf` 之前。
- 脚本用 `sshd -T` 读生效的值确认密码登录真的关了，不是只看自己写的文件。
- **执行时保持当前终端不关**，另开一个终端用密钥登录成功，再关掉旧的。
- 安装 fail2ban，反复登录失败的地址封一小时。

腾讯云防火墙只需要放行 22 / 80 / 443，其余删掉（尤其 Windows 远程桌面 3389）。

## 五、备案通过之后：打开 HTTPS

先把域名的 A 记录解析到服务器的公网 IP，等生效，再：

```bash
# 先试跑：用测试环境签，不占 Let's Encrypt 的正式额度（签出的证书浏览器不信任）
ssh <服务器别名> 'cd /root/language-learning && env WP_DOMAIN=<域名> WP_ACME_STAGING=1 bash word-puzzle/deploy/cloud/enable-tls.sh'
# 正式签发
ssh <服务器别名> 'cd /root/language-learning && env WP_DOMAIN=<域名> WP_ACME_EMAIL=<邮箱> bash word-puzzle/deploy/cloud/enable-tls.sh'
```

- 用 HTTP-01 验证：要求 80 端口能从公网访问。未备案的域名，国内机房的 80/443 会被拦截，这时会失败，
  脚本的报错里会提示"是否已备案"。
- 证书由 certbot 定时器自动续期，续期成功后自动重载 nginx。检查：`certbot renew --dry-run`。
- 之后网站在 `https://<域名>/word-puzzle/`，80 自动跳转到 443；用 IP 或别的域名访问会被断开。
- 微信里的链接用 `https://<域名>/word-puzzle/`。改了 JS / CSS 要先 `python3 word-puzzle/tools/bump_assets.py`（见 AGENTS.md）。

## 六、备份与快照

- 每天 03:00（北京时间）由 systemd 定时器备份数据库到 `/var/backups/lexica`，保留 30 份。
  **它和数据库在同一块盘上，只防误删和数据损坏，防不了服务器整个坏掉。**
- 所以还要：在腾讯云控制台给这台实例打**快照**（升级、改配置前手动打一次），并让家里的测试环境每天把备份拉回去
  （由家里发起，只读，见路线图里的"每日同步"）。
- 恢复：停服务 → 把备份文件复制成 `/var/lib/word-puzzle-family/app.db` → 属主改回 `wpfamily` → 起服务。

## 七、几条不能碰的规则

- **不要在这台服务器上装 frp、代理、VPN、反向隧道**：腾讯云轻量服务器禁止**流量穿透或非法代理**服务和 PCDN，
  违规会被告警、关停甚至清退。我们只跑 nginx 和词境后端，对外提供网站服务，属于正常用途。
- 锐驰型套餐的 200Mbps 是峰值上限，不是承诺指标，高峰期可能受影响；流量不限。
- 学生姓名、班级、访问记录都在这台机器上：密钥不要进仓库，`deploy.local.env`、`AGENTS.local.md` 留在本机。
- 国内服务器不是家里的网络：`apt` 已经走腾讯云镜像，PyPI 可用；Edge TTS（`en-US-AriaNeural`）实测可用，
  每个单词第一次合成约 2–3 秒、约 13KB，之后走缓存。

## 八、日常

```bash
systemctl status word-puzzle-family nginx           # 服务状态
journalctl -u word-puzzle-family -n 50              # 后端日志
tail -f /var/log/nginx/word-puzzle-cloud.access.log # 访问日志（443 入口）
tail -f /var/log/nginx/word-puzzle-family.access.log # 本机入口（隧道）的访问日志
fail2ban-client status sshd                         # 被封的地址
```
