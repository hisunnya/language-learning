# 词境 Lexica · 云服务器（生产）部署说明

生产环境是一台云上的 Debian 服务器（学生版，要登录）。后端、数据库、备份都在这一台上，
nginx 直接面对公网，不再经过 Tailscale Funnel。家里的 PVE 是测试环境，开发 VM 做单元测试。

> 域名、服务器地址、密钥路径这类私有值**不写进仓库**，只放在本机的 `AGENTS.local.md` 和 `~/.ssh/config`。
> 下面用 `<服务器别名>`、`<域名>` 代替。

## 一、这套脚本做什么

| 脚本 | 做的事 | 什么时候跑 |
|---|---|---|
| `install.sh` | 复用 `deploy/family/install.sh` 装后端、数据库、systemd、每日备份、看门狗、管理命令；再装公网 nginx（只认 `<域名>`） | 每次发布 |
| `render-nginx.sh` | 生成公网 nginx 配置：有证书就开 HTTPS，没有就只放行证书验证 | 被前两个脚本调用，也可单独跑 |
| `harden.sh` | SSH 只许密钥登录 + fail2ban | 装好后一次 |
| `enable-tls.sh` | 签 Let's Encrypt 证书、打开 HTTPS、设置自动续期 | **备案通过**、域名解析到本机之后一次 |

没有证书之前，网站**只能从服务器本机访问**：登录用的 Cookie 带 `Secure`，明文 http 暴露在公网既登不上，
账号密码也会明文走公网。所以备案期间用 SSH 隧道测试。

## 二、第一次部署

在你的电脑上（路径换成自己的，别把代码打进公开仓库以外的地方）：

```bash
COPYFILE_DISABLE=1 tar czf /tmp/lexica-src.tgz --exclude='word-puzzle/var' --exclude='__pycache__' --exclude='.DS_Store' --exclude='*/tests' --exclude='ham-exam/raw-files' --exclude='ham-exam/tools' word-puzzle hub topic-app/topic-app ham-exam chemistry physics backends
scp -q /tmp/lexica-src.tgz <服务器别名>:/tmp/lexica-src.tgz
ssh <服务器别名> 'mkdir -p /root/language-learning && tar xzf /tmp/lexica-src.tgz -C /root/language-learning && cd /root/language-learning && env DEBIAN_FRONTEND=noninteractive WP_DOMAIN=<域名> bash word-puzzle/deploy/cloud/install.sh'
```

不要在国内服务器上 `git pull`：到 GitHub 的连接又慢又不稳（实测一次请求要 8 秒）。代码从你的电脑或开发 VM 推过去。

装好后创建管理员：

```bash
ssh <服务器别名> 'wp-family-admin create-admin 你的工号 --name 你的名字'
```

## 三、备案期间怎么测试：SSH 隧道

转发写在 `~/.ssh/config` 里，**只要 `ssh <服务器别名>`，本机的 8081 就自动转到云上的 8081**，不用再手动写 `-L`：

```
Host lexica-bj
    HostName <服务器地址>
    User root
    IdentityFile ~/.ssh/<私钥>.pem
    LocalForward 127.0.0.1:8081 127.0.0.1:8081    # 本机自己用
    LocalForward <本机IP>:8081 127.0.0.1:8081     # 同一个 Wi-Fi 里的手机、平板
    ExitOnForwardFailure no                        # 转发没开成也不要连不上
    ServerAliveInterval 60
```

保持这个 ssh 窗口不关，就能打开：

| 谁打开 | 地址 |
|---|---|
| 本机自己 | `http://127.0.0.1:8081/` |
| 同一个 Wi-Fi 里的手机、平板 | `http://<本机IP>:8081/`（本机 IP 用 `ipconfig getifaddr en0` 查） |

走本机 IP 的那条路上会话 Cookie **不带** `Secure`（云服务器上的隧道入口按明文 http 处理，见
`deploy/family/install.sh` 里 `WP_CLOUD=1` 的那一段），所以浏览器会把它留下来 —— 如果带 `Secure`，
Chrome 只在安全来源（https 或 localhost）下才保存，用局域网 IP 打开就会「登录成功、刷新一下又要求登录」。

没有 ssh config 时也可以临时转发（效果一样，只是每次都要带参数）：

```bash
ssh -N -L 127.0.0.1:8081:127.0.0.1:8081 <服务器别名>
```

不要用 `http://公网IP` 测试：80 端口在没有证书时只放行证书验证；而且在国内未备案就向公众提供服务不合规。
这里的做法是自己一个人通过隧道看，不对学生开放，直到备案通过。

## 三·附、代码和数据怎么跟家里同步

云服务器和家里的机器**始终保持一致**（云上领先一步，备案一通过就能接手）。每次改动部署到家里之后，
在**你的电脑上**做两件事：

```bash
# 1) 代码：打包 → 传到云上 → 装（云上不用 git pull：到 GitHub 的连接又慢又不稳）
COPYFILE_DISABLE=1 tar czf /tmp/lexica-src.tgz --exclude='word-puzzle/var' --exclude='__pycache__' \
  --exclude='.DS_Store' --exclude='*/tests' --exclude='ham-exam/raw-files' --exclude='ham-exam/tools' \
  word-puzzle hub topic-app/topic-app ham-exam chemistry physics backends
scp -q /tmp/lexica-src.tgz <服务器别名>:/tmp/lexica-src.tgz
ssh <服务器别名> 'rm -rf /root/language-learning.new && mkdir -p /root/language-learning.new \
  && tar xzf /tmp/lexica-src.tgz -C /root/language-learning.new \
  && rm -rf /root/language-learning.old && mv /root/language-learning /root/language-learning.old \
  && mv /root/language-learning.new /root/language-learning \
  && cd /root/language-learning && env DEBIAN_FRONTEND=noninteractive WP_DOMAIN=<域名> \
     bash word-puzzle/deploy/cloud/install.sh'

# 2) 数据：把家里的数据库整体同步到云上（家里的服务照常运行，不用停）
export HOME_SSH=<登录家里 PVE 宿主机的 ssh 目标> HOME_CTID=<lexica 容器编号> \
       HOME_BACKUP_DIR=<宿主机上挂进容器 /backup 的目录> CLOUD_SSH=<云服务器别名>
bash word-puzzle/deploy/cloud/sync-from-home.sh rehearse --apply
```

两台机器上都是真实的学生数据，所以两台都只能私访（家里走 Funnel，云上走隧道）。`cutover`（停家里的服务、
正式切换）只在备案通过、真的要交给云上的时候才做。

## 四、SSH 加固（装好后一次）

```bash
ssh <服务器别名> 'cd /root/language-learning && bash word-puzzle/deploy/cloud/harden.sh'
```

- 脚本只在 root 的 `authorized_keys` 里已经有公钥时才继续，否则拒绝（防止把你锁在外面）。
- 它写 `/etc/ssh/sshd_config.d/00-lexica-hardening.conf`：关掉密码登录、`PermitRootLogin prohibit-password`。
  文件名以 `00-` 开头，是因为 sshd 取第一次出现的值，要排在腾讯云自带的 `50-cloud-init.conf` 之前。
- 脚本用 `sshd -T` 读生效的值确认密码登录真的关了，不是只看自己写的文件。
- **执行时保持当前终端不关**，另开一个终端用密钥登录成功，再关掉旧的。
- 安装 fail2ban，反复登录失败的地址封一小时。

腾讯云防火墙只需要放行 22 / 80 / 443，其余删掉（尤其 Windows 远程桌面 3389）。

## 五、备案通过之后：打开 HTTPS

先把域名的 A 记录解析到服务器的公网 IP，等生效，再：

```bash
# 先试跑：用测试环境签，不占 Let's Encrypt 的正式额度（签出的证书浏览器不信任）
ssh <服务器别名> 'cd /root/language-learning && env WP_DOMAIN=<域名> WP_ACME_STAGING=1 bash word-puzzle/deploy/cloud/enable-tls.sh'
# 正式签发
ssh <服务器别名> 'cd /root/language-learning && env WP_DOMAIN=<域名> WP_ACME_EMAIL=<邮箱> bash word-puzzle/deploy/cloud/enable-tls.sh'
```

- 用 HTTP-01 验证：要求 80 端口能从公网访问。未备案的域名，国内机房的 80/443 会被拦截，这时会失败，
  脚本的报错里会提示"是否已备案"。
- 证书由 certbot 定时器自动续期，续期成功后自动重载 nginx。检查：`certbot renew --dry-run`。
- 之后网站在 `https://<域名>/word-puzzle/`，80 自动跳转到 443；用 IP 或别的域名访问会被断开。
- 微信里的链接用 `https://<域名>/word-puzzle/`。改了 JS / CSS 要先 `python3 word-puzzle/tools/bump_assets.py`（见 AGENTS.md）。

## 六、备份与快照

- 每天 03:00（北京时间）由 systemd 定时器备份数据库到 `/var/backups/lexica`，保留 30 份。
  **它和数据库在同一块盘上，只防误删和数据损坏，防不了服务器整个坏掉。**
- 所以还要：在腾讯云控制台给这台实例打**快照**（升级、改配置前手动打一次），并让家里的测试环境每天把备份拉回去
  （由家里发起，只读，见路线图里的"每日同步"）。
- 恢复：停服务 → 把备份文件复制成 `/var/lib/word-puzzle-family/app.db` → 属主改回 `wpfamily` → 起服务。

## 六·附、把家里的数据整体迁到云上

生产在家里的时候，学生还在用，数据一直在变；云上这台在备案通过之前不对外。所以分两步：**演练**（可以反复做，
家里不停）和**正式切换**（只做一次，要停家里的服务）。换库的是 `migrate-data.sh`（在云上跑），
`sync-from-home.sh`（在你的电脑上跑）把"家里取备份 → 送到云 → 云上换"串起来。

**换上去之后，云上原来的账号和记录就没有了，整个数据库是家里的。** 之后用家里原来的管理员账号登录，密码也是家里的。
所以现在在云上建的管理员只是用来试，切换后会被替换。

私有值用环境变量给，不写进仓库（具体的值在 `AGENTS.local.md`）：

```bash
export HOME_SSH=<登录家里 PVE 宿主机的 ssh 目标>
export HOME_CTID=<lexica 容器编号>
export HOME_BACKUP_DIR=<宿主机上挂进容器 /backup 的目录>
export CLOUD_SSH=<云服务器别名>
```

### 1) 演练（家里照常运行）

```bash
bash word-puzzle/deploy/cloud/sync-from-home.sh rehearse            # 只检查，云上不改
bash word-puzzle/deploy/cloud/sync-from-home.sh rehearse --apply    # 真的换进云上（云上还没对外，可以反复做）
```

- 家里取一份 SQLite 在线备份（和每天的备份是同一个办法，不停服务，不会拷出半截的文件），数据只在家里宿主机和
  云服务器之间走，不在你的电脑上落地；云上的临时副本用完就删。
- 检查：完整性、**要运行的这版代码能不能打开它**（在临时副本上升级表结构，行数必须不变）、里面有没有账号
  （一个账号也没有说明拿错了文件，拒绝）。然后把"云上现在"和"备份"各自的账号、题库、成绩、访问记录并排列出来。
- `--apply` 时：先给云上当前的库存一份快照（`/var/backups/lexica/before-migration/`）→ 停服务 → 换库（清掉旧库的
  WAL / SHM，属主权限照旧）→ 起服务 → 健康检查 → 对一遍行数（人产生的数据一行都不能多也不能少；题库只许变多，
  后端启动时会补上缺的内置题库）→ 未登录访问 `/api/banks` 必须还是 401。**任何一步不对，自动把快照放回去**，退出码非 0。
- 演练是真数据：学生姓名、班级、IP 都会放到云上。云上没对外（只有 SSH 隧道能看），但仍然是学生数据，
  用完不需要的快照（`before-migration/` 里）要删。

### 2) 正式切换（备案通过之后，只做一次）

```bash
bash word-puzzle/deploy/cloud/sync-from-home.sh cutover --yes
```

1. 停掉家里的服务，**从这一刻起学生用不了**，确认真的停了；
2. 家里取备份（这时没有任何写入，是最终数据）→ 送到云 → 换上，流程和演练一样；
3. 成功：家里的服务**保持停止**，终端会提示接下来做什么；
4. 失败：脚本把家里的服务自动起回来（学生不该因为迁移失败一直用不了），云上自动回滚到切换前。

停机从第 1 步开始到第 3 步结束，通常几分钟（取决于数据库大小和网速）。切换后：域名解析到云服务器 →
`enable-tls.sh` → 用家里的管理员账号登录检查 → 学生换新网址。要退回家里：把家里的服务起来
（家里的数据停在切换那一刻，云上之后产生的新数据不会回来）。

### 不迁的东西

- 语音缓存（`var/audio`）和离线页（`var/offline`）：按需重新合成，实测 Edge TTS 在云上可用，每个词第一次约 2–3 秒。
- 家里的 nginx、Funnel、Tailscale：不动。

## 七、几条不能碰的规则

- **不要在这台服务器上装 frp、代理、VPN、反向隧道**：腾讯云轻量服务器禁止**流量穿透或非法代理**服务和 PCDN，
  违规会被告警、关停甚至清退。我们只跑 nginx 和词境后端，对外提供网站服务，属于正常用途。
- 锐驰型套餐的 200Mbps 是峰值上限，不是承诺指标，高峰期可能受影响；流量不限。
- 学生姓名、班级、访问记录都在这台机器上：密钥不要进仓库，`deploy.local.env`、`AGENTS.local.md` 留在本机。
- 国内服务器不是家里的网络：`apt` 已经走腾讯云镜像，PyPI 可用；Edge TTS（`en-US-AriaNeural`）实测可用，
  每个单词第一次合成约 2–3 秒、约 13KB，之后走缓存。

## 八、日常

```bash
systemctl status word-puzzle-family nginx           # 服务状态
journalctl -u word-puzzle-family -n 50              # 后端日志
tail -f /var/log/nginx/word-puzzle-cloud.access.log # 访问日志（443 入口）
tail -f /var/log/nginx/word-puzzle-family.access.log # 本机入口（隧道）的访问日志
fail2ban-client status sshd                         # 被封的地址
```
