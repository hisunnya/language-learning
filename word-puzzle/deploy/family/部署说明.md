# 词境 · 学生版 部署说明

带登录的版本：学生用**学号**登录，成绩按人记录，你（管理员）导入名单、重置密码、按班级导出成绩。
家庭版（`deploy/install.sh`）完全不变，两个版本可以装在同一台机器上，也可以分开装。

```
学生手机 --HTTPS--> Tailscale Funnel --HTTP--> nginx 127.0.0.1:8081 --> 后端 127.0.0.1:8766
```

后端和 nginx 都只监听本机，**对外的唯一入口是 Funnel**。

---

## 一、先看这几条（上线前必须过一遍）

1. **不要装在 PVE 宿主机上。** 在 PVE 里新建一个 LXC 容器或虚拟机（Debian 13 即可），
   只在里面装本程序和 Tailscale。宿主机上有 PVE 管理界面和 SSH，不要跟公网沾边。
   **完整步骤（建容器、放行 TUN、装 Tailscale、关密钥过期、备份）见 [`PVE容器部署.md`](PVE容器部署.md)。**
2. **主机名别叫 `PVE 宿主机`。** Funnel 的网址里带着机器名，起个中性的，例如 `lexica`：
   `sudo tailscale set --hostname=lexica`。
3. **tailnet 名字在发出网址之前定下来。** 管理后台 → DNS → Rename tailnet，只能从随机生成的里挑；
   以后再改，所有发出去的链接和二维码都会失效。
4. **这个网址是公开的。** 开 Funnel 后几分钟内就会有扫描器来探 `/.env`、`/AGENTS.md`、`/config.js` 之类
   （我们测试时实测过）。所以：登录必须开着、nginx 的拦截规则必须在、不要用 `python3 -m http.server` 之类临时服务
   对外开放（它会把当前目录下的所有文件都暴露出去）。
5. 容器里用到的是 Funnel 的 443 端口，**家里路由器不用做任何端口映射**（家宽在运营商级 NAT 后面，映射也没用）。

## 二、安装

在容器里，拿到完整的仓库（`git pull`），然后：

```bash
sudo env WP_PUBLIC_URL=https://lexica.tailXXXX.ts.net bash word-puzzle/deploy/family/install.sh
```

`WP_PUBLIC_URL` 是你之后会用的对外地址（还没开 Funnel 也要先定好，格式 `https://主机名`，不带斜杠）。
脚本会装好服务和 nginx，并做自检：未登录访问接口必须返回 401，不通过就报错退出。
它**不会**碰 Tailscale 和 Funnel。

可选环境变量：`WP_FAMILY_PORT`（后端，默认 8766）、`WP_FAMILY_NGINX_PORT`（默认 8081）、
`WP_FAMILY_INSTALL_DIR`、`WP_FAMILY_DATA_DIR`。

## 三、创建管理员、导入名单

```bash
sudo wp-family-admin create-admin 你的工号 --name 你的名字      # 会提示输入密码（不要写在命令里）
sudo wp-family-admin import /tmp/名单.xlsx --out /tmp/初始密码.csv
```

名单是 Excel（.xlsx）或 CSV（UTF-8 或 GBK 都行）。必须有「学号」「姓名」两列，
可选「班级」「学院」「院系」「初始密码」「标签」（见下一节）。**手机号等用不到的列不会被保存**（导入时会提示）。

- 每个学生得到一个随机的 8 位初始密码，写进你指定的 `初始密码.csv`（权限 600，明文，**发完请删除**）。
- 学生第一次登录必须先改成自己的密码；新密码至少 8 位、字母数字符号至少两种、不能含学号。
- 重复导入同一份名单不会重复建号，也不会动已有密码；加 `--reset-existing` 才会给已有学号重新发密码。
- 也可以登录后在网页的「账号管理」里上传名单、重置密码、停用账号、解锁、导出成绩。

其他命令：`reset-password 学号`、`unlock 学号`、`disable 学号`、`enable 学号`、`list [--class-name 班级]`。

规则：连续输错 5 次密码会锁定该账号 15 分钟（管理员可以提前解锁）；会话 14 天有效；
改密码或被重置后，该账号在其他设备上的登录全部失效。

## 三（续）、标签和分类：学生能看到哪些题库

学生版里，**学生只能看到、打开和自己至少有一个相同标签的题库**；题库管理只有老师账号能用。

| | 学生 | 老师 |
|---|---|---|
| 看到的题库 | 只有和自己标签相同的 | 自己建的、共享给自己的、内置的（超级管理员：全部）——见下面「多位老师」 |
| 玩、记成绩 | 只能在自己看得到的题库上 | 随便 |
| 建题库、删题库、上传资料、生成离线页、改标签 | 不能（页面上也看不到入口，服务端同样拒绝） | 能 |
| 首页 | 只有「选个题库」列表，按分类分组 | 还有生成题库、离线页、默认题库等 |

- **标签**决定权限；**分类**只用来整理（例如「教材同步」「考试词汇」），不影响谁能看到。
- 标签用逗号隔开，每个最多 20 个字、一个人或一个题库最多 10 个。
- 标签**按老师分开**：李老师给学生和题库打的「一班」和孙老师的「一班」互不相干，学生要和**同一位老师**打的标签对上才看得到。
- **没打标签的题库，学生看不到**。内置教材题库也一样，所以上线后要先给题库打标签。
- 家庭版（没有登录）不受影响，题库照旧全部可见。

怎么设置：

1. 给学生打标签：导入名单时加一列「标签」（有内容就整组替换，空着或没有这一列则保持原样）；
   或者在「账号管理」里点某个学生的「标签」按钮；也可以先用班级等筛选，再用上面的
   「批量改标签」一次给列表里所有学生加上或去掉标签。
2. 给题库设标签和分类：登录老师账号，在首页题库列表里点「设置标签」（决定谁能看到，面板里会实时显示
   「按这些标签，N 名学生能看到」）或「设置分类」（只用来整理，相当于书名）。两个按钮互相独立，改一个不影响另一个。
3. 学生重新打开首页就能看到变化，不需要重新登录。

**第一次启用时的步骤**（现有题库都还没有标签，学生会暂时什么都看不到）：
先给学生打好标签，再给要开放的题库打上相同的标签，最后用一个学生账号登录确认看得到。
内置教材题库在词库更新后会被自动重建，分类和标签会一起保留。

### 一本书，一个单元一个题库，批量开放

整本教材不做成一个大题库，而是**一个单元一个题库**：单元是最小的开放单位，开放与否仍然只由标签决定，
没有另外一套规则。

| 角色 | 是什么 |
|---|---|
| **分类** | 书名（例如「新视野大学英语 读写教程 第一册」），学生列表里按它分组 |
| **题库** | 一个单元，标题是「书名 · Unit 1 …」，按单元顺序排好 |
| **标签** | 开放给谁（班级）：学生和题库有一个相同标签就能看到 |

1. **建题库：** 工作台上传带 `unit` 列的资料（CSV / JSON / Word / PDF），勾选「按单元拆成多个题库」，
   生成。一次得到每个单元一个题库，分类默认是书名，**此时没有标签，学生还看不到**。
2. **开放：** 首页题库列表里，这本书的标题旁点「**批量开放**」：
   - 填「开放给（标签）」，或点下面列出的现有班级标签（旁边提示有多少名学生）；
   - 点预设，自动勾选单元：**整本书** / **上半部分（上学期）** / **下半部分（下学期）** / **前 N 个单元**
     （在旁边的框里填 N）/ 清空；勾完还可以手动加减；
   - 点「开放」（给选中的单元加上这个标签）或「收回」（去掉）。已经带这个标签的单元会显示「已开放」，
     提示里的数字只算真正改动的单元。
3. 随着教学进度，回来再点一次，比如这次选「前 5 个单元」。学生刷新页面就能看到，不需要重新登录。

要点：

- 想让不同班级进度不同，就用不同的班级标签各开各的。
- 单元之间互相独立：一个单元题库里补齐关卡用的「复习词」只来自本单元，不会带出别的单元的词。
- 「按单元拆成多个题库」对家庭版也能用（没有标签和开放这一步）。
- 接口（给脚本用）：`POST /api/banks` 加 `"split_units": true`；`POST /api/banks/tags`，
  body `{"bank_ids": [1, 2], "add": "一班"}`（或 `"remove"`）；`GET /api/admin/tags` 列出所有标签。都只有老师能调。

### 成绩汇总

「成绩记录」页对老师是**学生成绩汇总**：每个学生、每套题一行——班级、学号、姓名、玩了几次、**完成**几次、最高分、最低分、平均分、平均用时、最近一次。
点一行展开，看每一次的具体情况（时间、得分、配对、答错、最高连击、用时、通关关数、是否完成）。
上面可以按班级、题库筛选，或搜学号 / 姓名；「导出汇总 CSV」导出的就是当前筛选出来的这张表。学生在同一页只看到自己的行。

- **完成** = 一次把整套题的所有关都通关了。中途退出、时间到、只通了前几关（哪怕最后停下来的那一关配对全对）都不算完成。
  总关数是按题库当前的词现算的，所以题库改过以后，旧成绩的「完成」会按新的关数重新判断。
- **平均用时**是每一次从开始到结束的总时间（含看通关画面的时间）的平均值。
- 只有「做完或主动退出」时才会记一次成绩；直接关掉页面不会记。离线测试页的成绩存在学生自己的浏览器里，不会出现在这里。

## 三（再续）、多位老师：每位老师管自己的班级和题库

底层只有一个数据库，老师之间靠「名下有谁、有哪些题库」隔开，互相看不到对方的班级。

| | 超级管理员（`create-admin` 建的那位） | 老师 |
|---|---|---|
| 学生、成绩、访问记录 | 全部 | 只有自己名下的学生（自己导入的、超管分给自己的） |
| 题库 | 全部，含内置题库的分类 | 自己建的 + 共享给自己的 + 内置题库（内置的能打标签、不能删、不能改分类） |
| 上传的词表 | 全部 | 自己上传的 |
| 「老师与分配」页 | 有 | 没有 |

**加老师**：超管登录 →「老师与分配」→ 填工号、姓名（密码可留空，自动生成）→ 添加。初始密码**只显示这一次**，
交给老师；老师第一次登录必须改密码。也可以在服务器上：`sudo wp-family-admin create-teacher 工号 --name 姓名`。
老师登录后直接进题库工作台，用法和超管一样：上传资料生成题库、在「账号管理」导入自己的名单、打标签开放。

**共享和分配**（「老师与分配」→「共享与分配」）：选「题库」或「学生」，勾选（可搜索、全选），选一位老师，再选：

- **共享**：对方也能用 / 也能管，原来的老师照样有；
- **转给**：只归对方（原来的老师失去它，连同他在上面打的标签）；
- **取消共享**：从对方名下移走（连同对方的标签，所以对方的学生也就看不到了）。

**同一个学号被两位老师导入**：自动变成两位老师共享（导入结果里会写「共享 N」，操作记录里也有一条），
不会改动前一位老师那边的姓名、班级等资料。也就是说，**知道学号就能把学生导进自己名下**——每一次都有记录，
超管在「操作记录」里能看到，必要时用「取消共享」收回。

**删除不是真删**：老师在工作台删题库、在「账号管理」删学生（或者先按班级筛选，再「删除列表里的学生」删掉整个班），
只是打上删除标记，老师和学生都看不到了；超管在「老师与分配」→「已删除」里能看到是谁、什么时候删的，一键恢复。
删除共享给自己的题库 / 也挂在别的老师名下的学生，只是从自己名下移走，不影响别人。
内置题库不能删。删掉老师账号也是软删除：他马上退出登录，名下的学生和题库还在，超管可以转给别的老师或恢复账号。

**家庭版（内网不登录）**看到的是内置题库和超管的题库。

**升级时的数据迁移**是自动的：已有的学生全部挂到第一位超级管理员名下，已有的标签记在她名下，所以升级后什么都不用做，
学生看到的题库和以前一样。升级前照常备份数据库。

## 四、开 Funnel（确认过再开）

```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up                         # 浏览器里登录授权
sudo tailscale set --hostname=lexica
tailscale funnel --bg 8081                # 具体参数以 tailscale funnel --help 为准
tailscale funnel status
```

开之前对照检查清单：

- [ ] 容器里没有别的网页服务在监听（`ss -ltnp`），Funnel 只指向 8081
- [ ] `curl http://127.0.0.1:8081/word-puzzle/api/banks` 返回 401
- [ ] `curl -I http://127.0.0.1:8081/.env` 返回 404
- [ ] 管理员账号已经创建，并能登录、能看到「账号管理」
- [ ] 用**没装 Tailscale 的手机、关掉 Wi-Fi** 打开对外网址能看到登录页
      （装了同一个账号的设备解析到的是内网地址，没经过 Funnel，测不准）

关掉：`sudo tailscale funnel reset`。

## 四（续）、内网入口（家庭版）和数据放在哪里

**一个后端、两个前台、一份数据库**（全貌见仓库根目录 `docs/路线图.md` 第一节）：

- 公网入口（Funnel → `127.0.0.1:8081`）：全部要登录。
- 内网入口（容器 `<容器IP>:8082`，PVE 宿主机 的 `http://<服务器IP>/word-puzzle/` 转给它）：**做题不用登录**，成绩按设备记，访问记录照常；
  点到管理功能（账号、题库、标签、访问记录）才要**老师登录**，账号就是学生版的账号（因为本来就是同一个后端和数据库）。
- 区分入口靠 nginx 打的 `X-Wp-Entry: lan`：公网入口每次都清空它；后端还要求请求来自本机 nginx、且开了 `WP_LAN_GUEST=1`，三条同时满足才生效。
- 内网入口是明文 http（没有证书），所以它的会话 Cookie 不带 `Secure`；公网入口恒为 https，Cookie 仍带 `Secure`。
- 访问记录里记真实访客 IP：内网入口把转发链交给后端，后端跳过 `WP_TRUSTED_PROXIES`（PVE 宿主机 的 <服务器IP>）再取最后一环。

```bash
# 容器内：安装时带上这些变量（都是可选的）
env WP_PUBLIC_URL=https://lexica.xxxx.ts.net \
    WP_LAN_ADDR=<容器IP> WP_TRUSTED_PROXIES=<服务器IP> \
    WP_BACKUP_DIR=/backup \
    bash word-puzzle/deploy/family/install.sh
# PVE 宿主机 上：deploy-all-*.sh 默认把 /word-puzzle/api/ 转给 <容器IP>:8082（LEXICA_UPSTREAM 可覆盖，=none 退回本机后端）
```

**数据库放在容器外面**（容器尽量无状态）：

| 内容 | 位置（PVE 宿主机 宿主机） | 容器里的路径 |
|---|---|---|
| 数据库 | `/data01/lexica-data/` | `/var/lib/word-puzzle-family/` |
| 每日备份（保留 30 份） | `/data02/lexica-backup/`（另一块盘） | `/backup/` |

- 挂载：`pct set 120 -mp0 /data01/lexica-data,mp=/var/lib/word-puzzle-family` 和 `-mp1 /data02/lexica-backup,mp=/backup`，容器要重启一次。
- 容器是非特权的，宿主机目录的属主要写成「容器里 wpfamily 的编号 + 100000」，否则容器里写不进去。
- **PVE 的 vzdump 不会备份这种宿主机挂载目录**，所以备份靠容器里的 `lexica-backup.timer`（每天北京时间凌晨 3 点，用 SQLite 在线备份，备份后做完整性检查）。
  看状态：`systemctl list-timers lexica-backup.timer`、`journalctl -u lexica-backup`。
- 还原：停服务，把某个 `/backup/app-日期.db` 拷成 `app.db`（属主 `wpfamily`），删掉旧的 `app.db-wal` / `app.db-shm`，再启动。
- 以前 PVE 宿主机 上那套独立的家庭版后端已退役：`word-puzzle` 服务停掉，`/var/lib/word-puzzle/app.db` 原地保留当备份，不删除。
- 关掉内网入口：不带 `WP_LAN_ADDR` 重新运行安装脚本，入口和配置会被移除。
- 内网里任何设备能打开内网入口、能做题；进管理功能需要老师账号密码。

## 五、日常维护

- 备份：数据库就是 `/var/lib/word-puzzle-family/app.db` 一个文件。定期用
  `sqlite3 app.db ".backup '/备份目录/app-日期.db'"` 备份到另一块盘，或者让 PVE 对这个容器做定时备份。
  备份文件里有学号、姓名和密码哈希，同样要保管好。
- 日志：`journalctl -u word-puzzle-family`，nginx 的在 `/var/log/nginx/word-puzzle-family.*.log`。
  登录成功和失败、每个页面的访问都在数据库的访问记录里（老师页面「访问记录」），不用翻日志。
- 更新：`git pull` 后重新运行第二步的安装命令即可，数据库不会被覆盖。
- 学生的数据：名单里的学号、姓名、班级、学院、院系，加上成绩和下面的访问记录，全部永久保留，不会自动删除。
  毕业或不用时，在管理页停用账号；要删除数据用 sqlite 删对应行。
- 访问记录（老师页面「访问记录」）：谁（账号）、IP、设备型号、系统、浏览器（含微信等内置浏览器）、屏幕、时区、语言、
  网络类型、打开了哪些页面、每页在前台停留多久、登录成功和失败（失败的也记学号和原因）。表是 `page_views` 和 `login_events`，
  时间存 UTC 秒数；页面右上「导出完整 CSV」把所有列（含转发头原文）导出，时间换成北京时间。登录页写明了会记录这些。
  密码不会进记录。
- IP 怎么来的：nginx 把 Funnel 传来的 `X-Forwarded-For` 等头原样放进 `X-Wp-Edge-*`（外面伪造不了），
  后端取转发链里最后一个有效地址，同时把收到的所有转发头都存进 `forwarded` 列。
  **Funnel 会传访客的真实 IP**（2026-11-15 实测：经 Funnel 的请求记下的 IP 和发送者的公网 IP 一致）；
  如果以后「访问记录」页顶部出现「IP 都是本机地址」的提示，说明这条链路有变化，要重新检查。
- 服务按北京时间运行（`TZ=Asia/Shanghai`），老表里的时间字符串因此和用户看到的一致。

## 六、已知的限制

- Funnel 带宽有上限且不能调；本站流量小，一个班同时上课一般够用，如果卡顿再评估。
- Funnel 在国内的可达性取决于 Tailscale 的线路，实测可用，但无法保证长期稳定。
  万一不通，备选是带固定 IP 的 VPS + frp（要花钱），或者改用微信小程序版。
- 登录限流是「单账号锁定 + 全站总量」，目前没有按来源 IP 限流（Funnel 会传真实 IP，以后需要的话可以加）。
